title: Описать бизнес-процесс продажи ЖД билетов в Camunda Modeler и написать конфигурацию для его запуска
---
1. Нарисовать BPMN в Camunda Modeler, Сохранить как ticket-sale.bpmn, указать Process ID = ticket-sale
![](images/practice_8_bpmn.png)
2.  Написать JavaDelegate для каждого Service Task.
```java
// Поиск билетов
public class SearchTicketsDelegate implements JavaDelegate {
    public void execute(DelegateExecution execution) {
        String route = (String) execution.getVariable("route");
        // логика поиска
        execution.setVariable("ticketsFound", true);
    }
}

// Оплата
public class PaymentDelegate implements JavaDelegate {
    public void execute(DelegateExecution execution) {
        // логика оплаты
        execution.setVariable("paymentSuccess", true);
    }
}

// Выдача билета
public class IssueTicketDelegate implements JavaDelegate {
    public void execute(DelegateExecution execution) {
        // логика выдачи
        System.out.println("Билет выдан!");
    }
}
```
3. Конфигурация (Embedded)
```java
public class Main {
    public static void main(String[] args) {
        ProcessEngine engine = ProcessEngineConfiguration
            .createStandaloneInMemProcessEngineConfiguration()
            .buildProcessEngine();

        // Деплой процесса
        engine.getRepositoryService()
            .createDeployment()
            .addClasspathResource("ticket-sale.bpmn")
            .deploy();

        // Запуск процесса
        engine.getRuntimeService()
            .startProcessInstanceByKey("ticket-sale");
    }
}
```
4. Прописать зависимости
<!-- Embedded -->
<dependency>
    <groupId>org.camunda.bpm</groupId>
    <artifactId>camunda-engine</artifactId>
    <version>7.20.0</version>
</dependency>

<!-- H2 для хранения состояния -->
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <version>2.1.214</version>
</dependency>
5. Проверяем вывод в консоль

Итого что произойдет при деплое: 
1. Запускаем Main.java
2. Camunda поднимает движок — в памяти создаются ACT_* таблицы в H2
3. Деплоится ticket-sale.bpmn — процесс зарегистрирован в движке
4. Вызываем startProcessInstanceByKey — процесс пошёл по шагам
5. Каждый Service Task вызывает свой JavaDelegate по очереди:
    - SearchTicketsDelegate — ищет билеты
    - PaymentDelegate — проводит оплату
    - IssueTicketDelegate — выдаёт билет
6. Процесс доходит до конечного события и завершается
7. Приложение завершается, H2 очищается — данные не сохраняются между запусками так как база In-Memory
