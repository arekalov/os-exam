### Уровни зрелости REST по Ричардсону.
**Модель зрелости Ричардсона** — модель оценки того, насколько веб-сервис соответствует принципам REST, включает 4 уровня:

- **Уровень 0 — POX (Plain Old XML):** Взаимодействие через один endpoint (/api), часто с использованием HTTP как простого транспорта.
- **Уровень 1 — Resources:** Используются отдельные URI для разных ресурсов (/api/products, /api/orders/).
- **Уровень 2 — HTTP Verbs:** Используются HTTP-методы по их назначению и коды состояния.
- **Уровень 3 — Hypermedia Controls:** Ответы содержат ссылки на доступные действия и связанные ресурсы (HATEOAS).


Уровень 3 - наиболее зрелый с точки зрения модели, поскольку клиент получает информацию о доступных действиях непосредственно от сервера.

### HTTP-методы: GET, POST, PUT, PATCH, DELETE.
HTTP-методы определяют, какое действие клиент хочет выполнить над ресурсом.

- **GET.** Назначение: Получение ресурса. Пример: Получить /users/15.
- **POST.** Назначение: Создание ресурса или выполнение операции. Пример: Создать пользователя.
- **PUT.** Назначение: Полная замена ресурса. Пример: Полностью обновить /users/15.
- **PATCH.** Назначение: Частичное изменение ресурса. Пример: Изменить email пользователя.
- **DELETE.** Назначение: Удаление ресурса. Пример: Удалить /users/15.


### Идемпотентность и безопасность методов.
**Безопасный метод** (Safe) — метод, не предназначенный для изменения состояния ресурса на сервере.
**Идемпотентный метод** (Idempotent) — метод, повторное выполнение которого приводит к тому же конечному состоянию ресурса, что и однократное выполнение.
Идемпотентность особенно важна при повторной отправке запросов после сетевых ошибок. 

- **GET.** Безопасный: Да. Идемпотентный: Да.
- **POST.** Безопасный: Нет. Идемпотентный: Нет, по умолчанию.
- **PUT.** Безопасный: Нет. Идемпотентный: Да.
- **PATCH.** Безопасный: Нет. Идемпотентный: Зависит от реализации.
- **DELETE.** Безопасный: Нет. Идемпотентный: Да.


### HTTP-коды состояния: 2xx, 3xx, 4xx, 5xx.
HTTP Status Code — числовой код, который сервер возвращает в ответе, чтобы сообщить результат обработки запроса, делятся на 5 групп:
* 1xx - информационные ответа
* 2xx - Успешная обработка
* 3xx - Перенаправление 
* 4xx - Ошибка на стороне клиента
* 5xx - Ошибка на стороне сервера

Наиболее часто используемые коды:
- 200 OK — запрос успешно выполнен.
- 201 Created — ресурс успешно создан.
- 204 No Content — запрос выполнен, тело ответа отсутствует.
- 400 Bad Request — некорректный запрос.
- 401 Unauthorized — отсутствует действительная аутентификация.
- 403 Forbidden — доступ запрещён.
- 404 Not Found — ресурс не найден.
- 500 Internal Server Error — внутренняя ошибка сервера.

### Заголовки HTTP и согласование форматов данных.

**HTTP-заголовки**  — дополнительные поля HTTP-сообщения, содержащие метаданные о запросе или ответе.

Основные заголовки:
* Content-Type -	Формат данных в теле сообщения
* Accept	- Форматы ответа, которые принимает клиент
* Authorization	- Данные для аутентификации и авторизации
* Cache-Control	- Правила кэширования
* Content-Length	- Размер тела сообщения

**Согласование форматов данных** (Content Negotiation) — механизм выбора формата представления ресурса на основе предпочтений клиента и возможностей сервера. Пример Заголовок `Accept: application/json` сообщает серверу, что клиент предпочитает JSON.
