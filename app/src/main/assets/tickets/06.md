## Планировщики задач, Cron
**Периодические задачи** — автоматически выполняемые операции, запускаемые по заранее определенному расписанию, в отличие от разовых или событийно-управляемых задач. Позволяют автоматизировать рутинные действия без участия оператора. Пример: очистка временных файлов каждые 30 минут

**Планировщик задач** — программа, часто называемая сервисом ОС, которая запускает другие программы и определяются очередь задач в зависимости от различных критериев, как, например:
* наступление определённого времени;
* переход операционной системы в определённое состояние (бездействие, спящий режим и т. д.);
* поступление запроса от администратора через пользовательский интерфейс
* загрузка системы
* и т.д.

Могут управлять очередью задач в масштабе распределенного окружения (кластера).
Примеры: Portable Batch System, Slurm Workload Manage, Platforms LSF, Univa Grid Enghine, Moab. 

**Cron** — планировщик задач, используемый для выполнения задач (в фоновом режиме)
в указанное время в unix. Crontab - команда в unix, используемая для управления планировщиком Cron, crontab создает файл crontab, содержащий команды и инструкции для запуска демона cron.
**Crontab** - команда, используемая для управления планировщиком Cron. Команда crontab создает файл crontab, содержащий команды и инструкции для запуска демона cron, каждая запись в нем состоит из 6 полей в след. формате: `minute(s) hour(s) day(s) month(s) weekday(s) command(s)`

## Системы управления период. задачами
**Системы управления периодическими задачами** - частный случай планировщиков задач, предназначенные для запуска задач по заранее определенному расписанию в отличие от общих планировщиков ОС, учитывающих состояние системы. Обеспечивают выполнение заданий через фиксированные интервалы времени (каждые N минут/часов) или по календарному расписанию (ежедневно в 9:00, по понедельникам и т.д.), а также управляет очередью задач в распределенном окружении (кластере). Могут быть реализованы как спецальная программа или модуль в составе инфраструктурного ПО (Quartz внутри приложения) и находиться на разных уровнях инфрструктуры ПО. Правила запуска обычно задаются в конфигурации конкретной задачи или пользователя. 
**Примеры**: `Quartz` (Java-фреймворк), `Spring @Scheduled`, `EJB Timer Service` (Jakarta EE), `Jenkins` (для CI/CD), Airflow (для DAG-задач), `Apache Camel` (компонент scheduler).

### Прецеденты использования
* Задача состоит из нескольких шагов, зависящих друг от друга.
* Ошибка одного шага не должна убивать всю цепочку (нужны повторы, ручной перезапуск с места пдения).
* Задача должна выполниться ровно один раз (начисление средств, генерация отчёта, рассылка).
* Среда — кластер из 5+ серверов, и нельзя привязаться к одному узлу (как к cron).
* Нужен веб-интерфейс для мониторинга и ручного управления.

### Основные компоненты системы
* **Хранилище метаданных** — БД, где хранятся все DAG-и, история запусков, статусы тасков, контекст выполнения. Без него система забывает о задачах при перезапуске.
* **Планировщик** — процесс, который отслеживает расписание, создаёт объекты запуска (DAG Run) и кладёт таски в очередь. Он не выполняет код, а только решает, что и когда запустить.
* **Воркер (Worker)** — процесс (или множество процессов), который забирает таски из очереди и выполняет их. Может быть распределён по разным серверам.
* **Очередь задач (Queue)** — брокер сообщений (Redis, RabbitMQ) или таблица в БД для передачи тасков от спланировщика воркерам.
* **Веб-интерфейс** — просмотр логов, графов, ручной триггер, повтор неудачных запусков, пауза/возобновление DAG.
