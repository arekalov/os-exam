### Определение SOAP и его назначение
**SOAP (Simple Object Access Protocol)** — протокол обмена структурированными сообщениями между распределёнными приложениями, позволяет программным системам взаимодействовать друг с другом независимо от используемых языков программирования, ОС и платформ.   Основан на XML, является расширением стандарта XML-RPC. Базируется на идеологии RPC, cтандартизирован W3C. **Основная идея**: клиент формирует SOAP-сообщение в формате XML, отправляет его сервису, а сервис обрабатывает запрос и возвращает SOAP-ответ.

SOAP используется для:
- вызова удалённых операций;
- передачи данных между информационными системами;
- интеграции корпоративных приложений;
- организации взаимодействия между клиентом и сервером;
- обмена сообщениями с использованием дополнительных механизмов безопасности и надёжности.

### Основные принципы взаимодействия
Взаимодействие через SOAP обычно строится по модели запрос-ответ. Основные принципы:
- **Обмен сообщениями**. Взаимодействие осуществляется посредством структурированных SOAP-сообщений.
- **Стандартизированная структура**. Все SOAP-сообщения имеют установленную XML-структуру.
- **Независимость от платформы**. Клиент и сервер могут использовать разные языки программирования и операционные системы.
- **Независимость от транспорта**. SOAP не привязан исключительно к HTTP и может использовать различные транспортные протоколы.
- **Расширяемость**. Дополнительные функции реализуются с помощью стандартов семейства WS-*.

### Структура SOAP-сообщения
SOAP-сообщение представляет собой XML-документ с обязательным корневым элементом Envelope. Основные элементы:
1. **Envelope** — корневой элемент, обозначающий SOAP-сообщение, его начало и конец, а также пространство имён SOAP.
2. **Header** — необязательный заголовок с дополнительной служебной информацией.
3. **Body** — обязательная часть с основным содержимым сообщения (название вызываемой операции, параметры запроса, результат выполнения операции, данные, передаваемые между системами.).
4. **Fault** — элемент для передачи информации об ошибках; располагается внутри Body.

### Транспортные протоколы

SOAP не привязан к одному транспортному протоколу. Он определяет формат сообщений и правила их обработки, а транспорт отвечает за доставку сообщений между системами, однако самый распространённый вариант — SOAP поверх HTTP/HTTPS, однако есть и другие:

- **HTTP:** Наиболее распространённый вариант передачи SOAP-сообщений.
- **HTTPS:** HTTP с защитой TLS, обеспечивает шифрование и проверку подлинности сервера.
- **SMTP:** Может использоваться для передачи SOAP-сообщений по электронной почте.
- **TCP:** Может использоваться для прямой передачи данных между системами.



 ### Преимущества и недостатки SOAP
**Преимущества**
1. **Стандартизация** — строгая структура сообщений и правила взаимодействия.
2. **Независимость от платформы** — взаимодействие приложений на разных языках и ОС.
3. **Безопасность и надёжность** — поддержка WS-Security и WS-ReliableMessaging.
4. **Расширяемость** — дополнительные возможности через стандарты WS-*.
5. **Формальное описание** — WSDL описывает операции, параметры и типы данных сервиса.

**Недостатки:**
1. **Большой объём сообщений** — XML содержит много служебных тегов.
2. **Высокие вычислительные затраты** — обработка XML требует дополнительных ресурсов.
3. **Сложность разработки и настройки** — необходимо учитывать SOAP, XML и стандарты WS-*.
4. **Избыточность** — для простых API SOAP часто сложнее и тяжелее, чем REST.

### WS-* стандарты и расширения
WS- (Web Services Specifications)* — семейство стандартов и спецификаций, расширяющих возможности (безопасности, надёжности, адресации и управления транзакциями) веб-сервисов, включая SOAP.

Основные стандарты:

- **WS-Security:** Обеспечение безопасности SOAP-сообщений: аутентификация, цифровые подписи, шифрование.
- **WS-ReliableMessaging:** Обеспечение надёжной доставки сообщений, контроль повторов и порядка доставки.
- **WS-Addressing:** Передача информации об адресах отправителя и получателя, маршрутизации сообщений.
- **WS-AtomicTransaction:** Координация распределённых транзакций.
- **WS-Coordination:** Координация действий нескольких распределённых компонентов.
- **WS-Policy:** Описание требований и возможностей сервиса, например требований безопасности.
