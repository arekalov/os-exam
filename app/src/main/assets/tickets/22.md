## Назначение и архитектура

**Spring Data REST** автоматически публикует REST API поверх репозиториев Spring Data. Для стандартных операций не требуется писать отдельный контроллер: ресурсы и обработчики формируются на основе модели данных, методов репозитория и настроек экспорта.

Последовательность взаимодействия: **HTTP-запрос → контроллеры Spring Data REST → репозиторий Spring Data → хранилище данных**.

При использовании **Spring Data JPA** сущности описываются через `@Entity`, репозиторий работает с ними через JPA, а Spring Data REST предоставляет HTTP-доступ к его операциям.

```java
@RepositoryRestResource(path = "users")
public interface UserRepository extends JpaRepository<User, Long> {
    List<User> findByName(@Param("name") String name);
}
```

Публикуются коллекция `/users`, элементы `/users/{id}` и поиск `/users/search/findByName?name=Ann`. Ответы обычно используют **HAL**: данные сопровождаются ссылками на связанные ресурсы. Поддерживаются ассоциации, проекции, а для подходящих репозиториев — пагинация и сортировка.

## Преимущества и недостатки

**Преимущества:** быстрое создание CRUD API, сокращение повторяющегося кода, единообразные маршруты и автоматическая гипермедиа-навигация.

**Недостатки:** внешний API тесно связан с моделью сущностей и репозиториев; сложные бизнес-операции требуют дополнительного кода. Необходимо явно управлять экспортом, доступом и представлением данных.

## Сравнение подходов

- **Spring Data REST:** API формируется из репозиториев; удобен для стандартного доступа к данным.
- **Spring Web MVC REST:** контроллеры описываются вручную; позволяет независимо проектировать контракт, DTO и бизнес-операции.
- **JAX-RS:** стандарт Jakarta EE для ручного описания REST-ресурсов, реализуемый Jersey, RESTEasy и другими средствами.

Spring Data REST построен поверх Spring MVC и использует его инфраструктуру обработки запросов.
