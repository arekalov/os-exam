## Способы реализации аутентификации в Java

В Java-приложениях (особенно на базе Spring Security) существует несколько способов аутентификации. Самый простой — **HTTP Basic**: логин и пароль передаются в заголовке Authorization (в base64), что удобно для тестирования, но требует HTTPS из-за слабой защиты. Более классический подход — **сессии**: после логина сервер создаёт сессию (обычно через cookie `JSESSIONID`) и хранит состояние пользователя, что удобно для веб-приложений, но плохо масштабируется. Также используются формы логина (`form-based authentication`) и `OAuth2/OpenID Connect` — для входа через внешние сервисы (Google, GitHub и др.).

Современный и более масштабируемый подход — **JWT** (JSON Web Token): после успешной аутентификации сервер выдаёт токен, который клиент отправляет в каждом запросе (обычно в Authorization: Bearer). Такой способ не требует хранения состояния на сервере (stateless), хорошо подходит для микросервисов и REST API. Помимо этого, применяются API-ключи, двухфакторная аутентификация (2FA), а также кастомные схемы (например, HMAC-подписи). 

Выбор способа аутентификации зависит от требований: сессии удобны для традиционных веб-приложений, JWT — для распределённых систем, а OAuth2 — для интеграции с внешними провайдерами.
