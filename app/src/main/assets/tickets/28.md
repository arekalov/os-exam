## HTTP + WebSockets
HTTP + WebSockets — комбинированный подход к асинхронной доставке сообщений, часто используемый в веб-приложениях и микросервисных архитектурах как альтернатива или дополнение к специализированным протоколам (AMQP, MQTT).

### Архитектура
* HTTP — используется для отправки сообщений от клиента к серверу (однонаправленный запрос-ответ). Клиент инициирует соединение, отправляет сообщение и закрывает соединение.
* WebSockets — обеспечивает постоянное двунаправленное (full-duplex) соединение между клиентом и сервером поверх одного TCP-канала, позволяя серверу проталкивать сообщения клиенту без необходимости постоянного поллинга.


## Варианты реализации
* **STOMP over WebSockets** - STOMP  передается поверх WebSocket-соединения, используется в Spring WebSocket, ActiveMQ, RabbitMQ
* **MQTT over WebSockets** - MQTT-сообщения передаются через WebSocket (для IoT-панелей и браузерных клиентов)
* **REST + Server-Sent Events (SSE)** - Альтернатива WebSocket для односторонней (сервер -> клиент) потоковой передачи
* **WebSocket + JMS** - JMS-брокеры (ActiveMQ, Artemis) предоставляют WebSocket-шлюз для браузерных JMS-клиентов

## Плюсы
* Интеграция с веб-экосистемой - Браузеры нативно поддерживают WebSocket API и fetch/XMLHttpRequest
* Единый стек - Нет необходимости поднимать отдельный брокер сообщений - можно использовать API Gateway + очередь в памяти или Redis
* Двунаправленность - WebSocket позволяет серверу отправлять сообщения без запроса клиента, отлично для чатов, уведомлений, дашбордов
* Балансировка и масштабирование - HTTP + WebSocket легко балансируются через reverse-proxy (Nginx, HAProxy, Cloudflare)

## Минусы
* Отсутствие гарантий доставки (QoS, подтверждения, dead-letter) на уровне протокола
* При обрыве соединения неотправленные сообщения теряются
* Нет встроенной маршрутизации
* Плохая масштабируемость WebSocket-соединений - каждое потребляет ресурсы сервера
