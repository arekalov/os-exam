## Декларативный — @Transactional

Spring открывает транзакцию перед вызовом метода, фиксирует или откатывает по завершении. Откат — автоматически при `RuntimeException`.

```java
@Transactional
public void placeOrder(Order order) {
    orderRepo.save(order);
    inventoryRepo.decrease(order.getItemId());
}
```

**Параметры:**
- `propagation` — поведение при вложенных транзакциях (REQUIRED, REQUIRES_NEW, NESTED и др.)
- `isolation` — уровень изоляции (READ_COMMITTED и др.)
- `readOnly = true` — оптимизация для read-only операций
- `rollbackFor` — классы исключений для отката (по умолчанию RuntimeException)
- `timeout` — таймаут в секундах

## Программный — TransactionTemplate

Явный контроль над границами транзакции:

```java
txTemplate.execute(status -> {
    accountRepo.debit(amount);
    return null;
});
```

`TransactionTemplate` инициализируется через `PlatformTransactionManager`.

## Программный — TransactionManager напрямую

Самый низкоуровневый способ:

```java
TransactionStatus status = txManager.getTransaction(new DefaultTransactionDefinition());
try {
    // логика
    txManager.commit(status);
} catch (Exception e) {
    txManager.rollback(status);
}
```
