### Понятие ресурса.
**Ресурс** — основной единицей взаимодействия REST, любой объект или сущность предметной области (пользователь, товар, заказ, документ,  коллекция объектов), с которыми взаимодействует клиент через REST API. Клиент обращается к ресурсу по его идентификатору, а сервер предоставляет его представление.

### Идентификация ресурсов с помощью URI.
**URI** (Uniform Resource Identifier) — унифицированный идентификатор ресурса, позволяющий однозначно обратиться к нему. В RESTful API для идентификации ресурсов обычно используются URL, являющиеся разновидностью URI. Для взаимодействия с ресурсами применяются HTTP-методы (GET/POST...)
Таким образом, URI определяет, с каким ресурсом работает клиент, а HTTP-метод — какое действие выполняется.

### Представление ресурса (Representation).
**Представление ресурса** (Representation) — форма (JSON/XML), в которой данные ресурса передаются клиенту или от клиента серверу. Сам ресурс не привязан к конкретному формату данных и может иметь несколько представлений.

### Форматы представления: JSON, XML и другие.
REST не ограничивает API одним форматом данных, который обычно указывается в заголовке `Content-Type`. Наиболее распространённые варианты:
* JSON	- Компактный, простой для обработки, широко используется в REST API
* XML	- Поддерживает сложную структуру и схемы данных
* HTML - Используется для представления данных в браузере
* Plain Text - 	Обычный текст
* Binary	- Изображения, файлы и другие бинарные данные

Заголовок `Accept` позволяет клиенту указать, какой формат ответа он предпочитает.

### Понятие payload.
**Payload** — содержимое HTTP-сообщения, непосредственно передающее данные ресурса, В REST API обычно находится в теле HTTP-запроса или ответа.


### Отличие ресурса от его представления.
Важно различать сам ресурс и его представление:
| Ресурс	| Представление| 
|---|---|
| Абстрактная сущность предметной области	| Форма передачи данных о ресурсе| 
| Существует независимо от формата	| Зависит от выбранного формата| 
| Идентифицируется через URI	| Передаётся в теле HTTP-сообщения| 
| Например, пользователь №15	| JSON или XML с данными пользовател|
