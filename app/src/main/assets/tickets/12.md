## Kafka

**Kafka** - популярный open-source сервис обмена сообщениями от Apache, построенный на основе Java и Scala. Изначально он работает как ориентированное на сообщения промежуточное программное обеспечение. Не совместим с JMS, требуется адаптер. Сообщения хранятся в структуре данных, сходной с журналом транзакций в СУБД. Поддерживается только модель доставки "Подписка"

### Архитектура
Kafka работает как кластер из одного или нескольких серверов (брокеров), которые хранят потоки  records в категориях, называемых topics. Внутри темы данные разбиваются на partitions, обеспечивая горизонтальное масштабирование и параллельную обработку  Каждая запись в партиции имеет уникальный  offset, и порядок записей строго гарантируется внутри отдельной партиции

### Область применения 
Kafka используется в сценариях, где требуется обработка больших объемов данных в реальном времени и возможность перечитывать историю событий:
* Потоковая обработка — пайплайны реального времени (аналитика, мониторинг, ML)
* Агрегация логов — централизованный сбор логов со всех серверов
* Event Sourcing / CDC — хранение всех изменений состояния как последовательности событий
* Метрики и трекинг — сбор действий пользователей и метрик приложений
* Финансовые транзакции — обработка платежей, мониторинг мошенничества
Не следует использовать в случае простая task-очередь, малые объёмы данных, синхронный RPC, когда не нужна история событий.

### Плюсы
* Очень высокая (миллионы сообщений в секунду), на порядки выше чем ActiveMQ/RabbitMQ
* Есть хранение истории
* Хорошая горизональная масштабируемость за счет добавления брокеров
* Отказоустойчивость за счет репликации партиций
* Мощная экосистема

### Минусы 
* Высокая сложность эксплуатации
* Отсутствие глобального порядка сообщений
* Ресурсоемкость по памяти и месту на диске
* Нет JMS-совместимости
* Не подходит для короткоживущих задач, когда сообщения должен быть удаления сразу после обработки

### Интеграция с Service Discovery
**Service Discovery** — механизм, позволяющий клиентам (producer/consumer) динамически находить брокеры Kafka в кластере без жёсткой привязки к конкретным адресам. Происходит следующим образом:
1. Клиент подключается к bootstrap-серверам, одному или нескольким известным адресам брокеров
2. Отправляет запрос Metadata, получая полный список всех брокеров кластера, их hostname/port, а также информацию о том, какой брокер является лидером для каждой партиции 
3. После этого клиент устанавливает прямые соединения с нужными брокерами, минуя bootstrap-сервер

Также для контейнерных сред (Docker/Kuberneters) используются инструменты типа `Strimzi`, автоматически генерирующие сервисы с лейблами, которые клиенты могут обнаруживать через API Kubernetes
