## Spring Boot vs обычный Spring
Обычный Spring требует ручной настройки множества компонентов (например, `DispatcherServlet, ViewResolver`, источников данных). **Spring Boot** - набор утилит для автоматизации процессов настройки, создания и
развертывания приложения, призванный решить проблему «ада конфигурации» через автоконфигурацию (`@EnableAutoConfiguration`) и избавить от необходимости повторять рутинные действия. Он анализирует зависимости в classpath, свойства и создаёт бины по умолчанию. Если в classpath есть `Tomcat` — Boot настроит встроенный сервер; есть H2 — сконфигурирует DataSource.

Ключевые преимущества: 
* Встроенный `Tomcat` (или Jetty/Undertow) позволяет запускать приложение как обычный Java-класс с main(), без развёртывания WAR в отдельный контейнер. 
* Управление зависимостями через стартеры (spring-boot-starter-web, starter-data-jpa) гарантирует совместимые версии библиотек. 
  
В итоге разработка ускоряется в разы: не нужно писать boilerplate-код, достаточно аннотаций `@SpringBootApplication` и нескольких свойств. Также включает в себя Spring Boot profiles - механизм изоляции конфигураций для разных сред (dev, test, prod)
