**Дополнительные возможности:**
* **Параметризация:** CSV Data Set Config, User Defined Variables, `${__Random()}`, `${__threadNum}`
* **Корреляция:** RegEx Extractor, JSON/XPath Extractor — session ID, token из ответа
* **Скрипты:** BeanShell, JSR223 (Groovy)
* **Non-GUI:** `jmeter -n -t plan.jmx -l results.jtl -e -o report/` (без Listeners в GUI)
* **Плагины:** jmeter-plugins.org; Backend Listener → InfluxDB + Grafana
* **CI/CD:** Maven plugin, Jenkins

**Распределённое тестирование:**
* **Master** — управляет, собирает результаты
* **Slave** — `jmeter-server`, генерирует нагрузку
* Связь через RMI (порт 1099)
* Запуск: `jmeter -n -t plan.jmx -R slave1,slave2 -l results.jtl`
* 1000 threads на 4 Slave ≈ 250 на каждый

**Требования:** одинаковая версия JMeter; открыты порты; CSV доступен на всех Slave; Listeners только на Master.

Для >5000 пользователей — несколько Slave или облако (BlazeMeter).
