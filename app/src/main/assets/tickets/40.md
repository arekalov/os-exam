## Решение

Spring Data REST автоматически создаёт HTTP-ресурсы для публичного репозитория и его CRUD-операций. В приложении подключены `spring-boot-starter-data-rest`, Spring Data JPA и настроена база данных. `Car` — существующая JPA-сущность с полями `id` и `brand`.

```java
import java.util.List;
import org.springframework.data.repository.CrudRepository;
import org.springframework.data.repository.query.Param;
import org.springframework.data.rest.core.annotation.RepositoryRestResource;

@RepositoryRestResource(path = "cars", exported = true)
public interface CarRepository extends CrudRepository<Car, Long> {
    List<Car> findByBrand(@Param("brand") String brand);
}
```

В `application.properties`:

```properties
spring.data.rest.detection-strategy=default
```

Публичные методы `CrudRepository` уже наследуются: повторно объявлять `save`, `findAll`, `findById` и `deleteById` не требуется. Ограничения `@RestResource(exported = false)` с нужных методов удаляются. Если ранее был отключён экспорт методов по умолчанию, в `RepositoryRestConfigurer` восстанавливается `config.setExposeRepositoryMethodsByDefault(true)`.

## Доступные операции

- `GET /cars` — список автомобилей (`findAll`).
- `GET /cars/{id}` — автомобиль по идентификатору (`findById`).
- `POST /cars` — создание (`save`).
- `PUT /cars/{id}`, `PATCH /cars/{id}` — замена и частичное обновление (`save`).
- `DELETE /cars/{id}` — удаление (`deleteById` / `delete`).
- `GET /cars/search/findByBrand?brand=Toyota` — вызов объявленного поискового метода.

Spring Data REST экспортирует операции над ресурсами, а не отдельный URL для каждого Java-метода. Например, `saveAll` и `count` не получают автоматически адреса `/saveAll` и `/count`; для таких отдельных операций нужен собственный контроллер.
