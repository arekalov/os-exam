## JCA, JCE и провайдеры

**JCA (Java Cryptography Architecture)** — архитектура криптографии Java: единый API для хешей, подписей, ключей, сертификатов и других операций.

**JCE (Java Cryptography Extension)** — историческое расширение JCA для шифрования, MAC и согласования ключей; входит в стандартную Java. Основные пакеты — `java.security` и `javax.crypto`.

Реализации алгоритмов предоставляют **провайдеры**. Приложение запрашивает алгоритм через `getInstance(...)`, а провайдер выполняет операцию. Так API не привязан к одной реализации; доступность алгоритмов зависит от JDK и провайдеров.

## Основные API

- **MessageDigest** — хеширование: SHA-256, SHA-512.
- **Signature** — создание и проверка подписи: `SHA256withRSA`, `SHA256withECDSA`. `initSign(privateKey)` / `initVerify(publicKey)` → `update(data)` → `sign()` / `verify(signature)`.
- **Cipher** — шифрование и дешифрование, например `AES/GCM/NoPadding`. `init(...)` → `doFinal(data)`.
- **KeyPairGenerator** — пары ключей RSA, EC; **KeyGenerator** — симметричные ключи AES.
- **KeyAgreement** — согласование общего секрета, например ECDH.
- **Mac** — код аутентификации, например `HmacSHA256`.
- **SecureRandom** — криптографически стойкие случайные значения для ключей и параметров; обычный `Random` для этого не подходит.
- **KeyStore**, **CertificateFactory**, **CertPathValidator** — хранилища, чтение сертификатов и проверка цепочек.

Пример SHA-256:

```java
byte[] hash = MessageDigest.getInstance("SHA-256")
    .digest("hello".getBytes(StandardCharsets.UTF_8));
```

AES-GCM использует симметричный ключ и уникальный для него nonce, а при расшифровании проверяет тег подлинности.

## Стандарты и защищённое взаимодействие

**X.509** задаёт формат сертификатов, **PKCS12** — хранилища, **PKCS#10** — CSR. **TLS** реализуется средствами **JSSE**, использующими криптографические механизмы Java. В корпоративных приложениях TLS обычно настраивается на уровне HTTP-клиента, сервера приложений или контейнера.
