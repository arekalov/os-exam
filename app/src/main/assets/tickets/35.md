**Penetration Testing** — имитация атаки на систему **авторизованными специалистами** с целью выявить уязвимости, которые могут использовать злоумышленники. Это активное тестирование безопасности «извне» (и при необходимости изнутри) с реальной эксплуатацией найденных слабых мест.

**Цели pentest:**
* найти уязвимости до атакующего
* оценить реальный риск для бизнеса
* проверить эффективность защитных механизмов и мониторинга

**Типы pentest по знанию системы:**
* **Black-box** — атакующий не знает внутреннюю архитектуру (как внешний хакер)
* **Gray-box** — частичное знание (роль пользователя, документация, схема сети)
* **White-box** — полный доступ к коду, конфигурации, архитектуре

**Этапы pentest (упрощённо):**
1. **Reconnaissance** — сбор информации (домены, порты, технологии)
2. **Scanning** — сканирование уязвимостей
3. **Exploitation** — попытка эксплуатации
4. **Post-exploitation** — оценка масштаба компрометации
5. **Reporting** — отчёт с рисками и рекомендациями

**DAST (Dynamic Application Security Testing)** — **динамический** анализ безопасности **работающего** приложения. Инструмент отправляет запросы к приложению и анализирует ответы, ища уязвимости (SQLi, XSS, CSRF и др.).

**Сравнение подходов к тестированию безопасности приложений:**
* **SAST** (Static) — анализ **исходного кода** без запуска
* **DAST** (Dynamic) — анализ **работающего** приложения снаружи
* **IAST** (Interactive) — анализ **во время выполнения** с агентом внутри приложения
* **SCA** — анализ **зависимостей** и известных CVE в библиотеках

**DAST — плюсы:**
* не нужен доступ к исходному коду
* видит реальное поведение приложения и конфигурации сервера
* находит проблемы интеграции, аутентификации, сессий

**DAST — минусы:**
* позднее обнаружение (нужно развёрнутое приложение)
* возможны ложные срабатывания
* сложнее покрыть редкие ветки логики
