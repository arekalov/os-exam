## Симметричное и асимметричное шифрование

**Симметричное шифрование** использует один общий секретный ключ для шифрования и дешифрования.

- Быстрое, подходит для больших объёмов данных.
- Главная проблема — безопасно передать или согласовать ключ.
- **AES** — блочный шифр, ключи 128/192/256 бит. Режим **AES-GCM** обеспечивает шифрование и проверку целостности; nonce нельзя повторять с тем же ключом.

**Асимметричное шифрование** использует математически связанную пару ключей — публичный и приватный. Публичный доступен участникам обмена, приватный хранится у владельца.

- При шифровании для получателя используют его публичный ключ, расшифровывает он своим приватным.
- Электронная подпись создаётся приватным ключом и проверяется публичным.
- **RSA** используется для шифрования или подписи с соответствующими схемами дополнения. Медленнее симметричных алгоритмов.
- **ECC** — семейство методов на эллиптических кривых: ECDH для согласования секрета, ECDSA для подписи.

**Гибридный подход:** асимметричные механизмы помогают аутентифицировать стороны и установить общий секрет; сами данные шифруются симметрично. Так устроен TLS.

## Сертификат X.509

Сертификат X.509 связывает публичный ключ с субъектом; связь заверяется подписью издателя. Приватного ключа в сертификате нет.

Основные поля:

- версия, серийный номер;
- **Issuer** — издатель, **Subject** — субъект;
- срок действия: `Not Before`, `Not After`;
- публичный ключ и его алгоритм;
- расширения: **SAN** с именами узлов, **Key Usage / Extended Key Usage** с назначением ключа, **Basic Constraints** с признаком CA;
- алгоритм подписи и подпись издателя.

Сертификат позволяет проверить принадлежность ключа; доверие устанавливается через цепочку до доверенного CA либо явное доверие конкретному сертификату.
