## JMS
**JMS** (Java Message Service) — стандарт Java API для создания, отправки, получения и чтения сообщений между компонентами распределенных приложений. Он обеспечивает асинхронную, слабосвязанную и надежную коммуникацию через очереди (point-to-point) или топики (publish/subscribe). Любой компонент, использующий JMS, прежде всего должен создать соединение с JMS провайдером. Для этого, нужно создать необходимые **ресурсы**. **Группа ресурсов JMS** – модуль адаптера ресурсов, обеспечивающий связывание фабрик соединений, очередей и т. п., которые можно получить с помощью JNDI lookup.

## Что включает спецификация JMS

1. Основные интерфейсы API:
   1. `ConnectionFactory` -	Фабрика для создания соединений с брокером (администрируемый объект)
   2. `Destination` -	Пункт назначения: очередь (Queue) или топик (Topic)
   3. `Connection` -	Активное соединение с провайдером (создает сессии)
   4. `Session` -	Контекст для производства и потребления сообщений (однопоточный)
   5. `MessageProducer` -	Отправитель сообщений в Destination
   6. `MessageConsumer` -	Получатель сообщений из Destination
   7. `Message` -	Собственно сообщение + заголовки + свойства + тело
   8. `MessageListener` -	Интерфейс для асинхронного приема (метод onMessage())
2. Модели доставки сообщений:
   1. Point-to-Point (P2P) - используется когда нужно чтобы сообщение отправлялось только 1 потребителю и характеризуется следующим. Сообщение попадает в queue адресата и может быть прочитано когда угодно, после обработки удаляется
   2. Publish/Subscribe (Pub/Sub) - используется, когда нужно распределить сообщение по всем потребителям и характеризуется следующим. Подписчик подписывается на определённую «тему» (**topic**), могут подписывать на несколько. Издатель публикует своё сообщение, которое получают все подписчики этой темы
3. Типы сообщений: `TextMessage, BytesMessage, MapMessage, ObjectMessage, StreamMessage`
4. Структура сообщения:
   1. **Заголовок** – содержит информацию, которая используется для маршрутизации и идентификации сообщений (обязательный). Заголовок хранит мета информацию сообщения, заполняемую автоматически (JMSCorrelationID, JMSDeliveryMode, JMSDestination).
   2. **Свойство** – содержит информацию, которую можно использовать для фильтрации сообщений (время, дата и т. п.). Поле свойств схоже с заголовком, но оно заполняется программно, и позже получатель сможет прочитать эту информацию.
   3. **Тело** – содержит информацию о типе сообщения (определяется при создании сообщения) и полезную нагрузку.
5. Администрируемые объекты - объекты, которые создаются администратором (через консоль сервера) и ищутся клиентом через JNDI:
   1. `ConnectionFactory` - Инкапсулирует параметры подключения к брокеру (хост, порт, логин/пароль, пулы)
   2. `Destination` - Абстрагирует физическое имя очереди/топика от клиентского кода
