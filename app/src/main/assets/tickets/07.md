### Определение и назначение WSDL
**WSDL** (Web Services Description Language) — язык описания веб-сервисов на основе XML, предназначенный для формального определения интерфейса веб-сервиса и правил взаимодействия с ним. **Основное назначение WSDL** — предоставить машинно-читаемое описание веб-сервиса, чтобы клиентские приложения могли взаимодействовать с ним без необходимости знать внутреннюю реализацию. WSDL позволяет клиенту узнать:
- какие операции предоставляет сервис;
- какие параметры принимает каждая операция;
- какие данные возвращает сервис;
- какие типы данных используются;
- по какому протоколу осуществляется взаимодействие;
- по какому сетевому адресу доступен сервис.

Может автогенерироваться по API сервиса, или, наоборот – API сервиса может
автогенерироваться по WSDL.

### Структура и элемента WSDL-документа
WSDL-документ представляет собой XML-файл, содержащий описание интерфейса и способа взаимодействия с веб-сервисом.

В классической версии WSDL 1.1 выделяют шесть основных элементов, в следующей последовательности:
1. **Types** — описание типов отправляемых и получаемых сервисом XML-сообщений, обычно в виде XSD
2. **Message** — описание структуры сообщений, которое передаётся между клиентом и сервисом. Сообщение может содержать один или несколько элементов part, ссылающихся на определённые типы данных или кастомные типы, объявленные через Types.
3. **PortType** — описание операций сервиса, которые могут быть выполнены с сообщениями, включает входные (input) и выходные (output) , а также опционально сообщения ошибок (fault)
4. **Binding** — описание конкретного способа доставки сообщения (протокола, версия протокола, формата передачи сообщения (http), особенности кодирования данных).
5. **Port** — конкретная точка доступа к сервису, связывает конкретный Binding с сетевым адресом (endpoint)
6. **Service** — объединение точек доступа (Port) в один сервис.

### Свззь WSDL и SOAP

WSDL и SOAP часто используются совместно, но выполняют разные задачи
- WSDL описывает веб-сервис: его операции, параметры, типы данных, протокол и адрес.
- SOAP обеспечивает обмен сообщениями: определяет формат и правила формирования SOAP-запросов и ответов.

Пример взаимодействия:
1. Разработчик получает WSDL-документ сервиса.
2. Изучает доступные операции, параметры и адреса.
3. На основании WSDL генерирует клиентский код или самостоятельно формирует запрос.
4. Клиент создаёт SOAP-сообщение в соответствии с описанием.
5. Отправляет его на endpoint сервиса.
6. Сервис обрабатывает запрос и возвращает SOAP-ответ.

### XML Schema (XSD)
**XML Schema Definition (XSD)** — язык на основе XML для описания структуры, типов данных и ограничений XML-документов. XSD используется в WSDL внутри элемента Types для определения типов данных, которыми обмениваются клиент и сервис. XSD позволяет определить:
- допустимые XML-элементы и атрибуты;
- типы данных (string, int, date, boolean и другие);
- обязательность и последовательность элементов;
- минимальное и максимальное количество элементов;
- ограничения на значения данных.

**Преимущества XSD по сравнению с XML:**
- строгая проверка структуры XML;
- контроль типов данных;
- выявление некорректных сообщений до их обработки;
- возможность автоматической генерации классов и структур данных.
