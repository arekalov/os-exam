## Транзакция в БД

Управляется СУБД командами `BEGIN` / `COMMIT` / `ROLLBACK`. Охватывает только операции одной БД. Атомарность и изоляция гарантируются на уровне БД.

## Транзакция на уровне бизнес-логики

Управляется прикладным кодом через API (Spring `@Transactional`, JTA `UserTransaction`). Может объединять несколько операций над несколькими ресурсами (несколько БД, очереди).

## Ключевые отличия

- **Граница** — в БД: один SQL-запрос или явный BEGIN/COMMIT; в БЛ: метод сервиса, который вызывает несколько репозиториев
- **Ресурсы** — БД-транзакция работает с одной СУБД; БЛ-транзакция может охватывать несколько (через JTA/XA)
- **Propagation** — БЛ управляет тем, как вложенные вызовы участвуют в транзакции (REQUIRED, REQUIRES_NEW, NESTED)
- **Абстракция** — Spring `PlatformTransactionManager` скрывает конкретную реализацию: JDBC, JPA, JTA

## Где ставить границу

Граница транзакции — на сервисном уровне, а не в репозитории. Репозиторий — только доступ к данным, сервис — бизнес-операция.

```java
@Service
public class OrderService {
    @Transactional // граница здесь
    public void placeOrder(Order order) {
        orderRepo.save(order);
        inventoryRepo.decrease(order.getItemId());
    }
}
```

## Проблемы на уровне БЛ

- **Lazy loading вне транзакции** — попытка загрузить связанную сущность после закрытия сессии → `LazyInitializationException`
- **Long conversation** — транзакция живёт дольше одного запроса → блокировки, конфликты
