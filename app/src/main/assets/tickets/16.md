## Логическое резервное копирование

**Логическое резервное копирование** — создание резервной копии в виде SQL-команд (CREATE TABLE, INSERT) или специального бинарного формата, описывающего структуру и данные. Не привязано к версии PostgreSQL и физическому расположению файлов.

### Утилиты

**pg_dump** — резервное копирование одной базы данных:
```bash
pg_dump -U postgres -F c -f backup.dump mydb   # формат custom (сжатый)
pg_dump -U postgres -F p -f backup.sql mydb    # plain SQL
pg_dump -U postgres -F d -f backup_dir/ mydb  # directory (параллельно)
```

**pg_dumpall** — резервное копирование всего кластера (все БД + глобальные объекты: роли, табличные пространства):
```bash
pg_dumpall -U postgres -f all.sql
```

**pg_restore** — восстановление из форматов custom, directory, tar (не plain SQL):
```bash
pg_restore -U postgres -d mydb -F c backup.dump
pg_restore -U postgres -d mydb --jobs=4 backup.dump  # параллельное восстановление
```

### Форматы pg_dump
* **plain (-F p)** — чистый SQL, читаем, восстанавливается через `psql`. Нельзя выбирать объекты при восстановлении.
* **custom (-F c)** — сжатый бинарный формат, поддерживает выборочное восстановление и параллелизм через pg_restore.
* **directory (-F d)** — каждый объект в отдельном файле, позволяет параллельный дамп (`--jobs`).
* **tar (-F t)** — архив TAR, поддерживает выборочное восстановление.

### Особенности
* Дамп снимается в рамках одной транзакции (консистентный снимок), не блокируя другие транзакции.
* Можно делать резервную копию отдельных схем (`-n schema`) или таблиц (`-t table`).
* Не сохраняет WAL и не подходит для Point-in-Time Recovery — только полный снимок на момент запуска.
