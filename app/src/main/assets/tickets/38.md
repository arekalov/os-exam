---

**Security testing нужно встраивать на всех этапах ЖЦ**, а не только перед релизом. Чем раньше найдена уязвимость — тем дешевле исправление.

**Waterfall (каскадная модель):**
* **Requirements** — security requirements, threat modeling
* **Design** — security architecture review
* **Implementation** — SAST, code review, secure coding standards
* **Testing** — DAST, pentest, vulnerability scan
* **Release** — final security assessment
* **Maintenance** — мониторинг, patch, re-test после исправлений

**Agile / Scrum:**
* security user stories и acceptance criteria в каждом спринте
* threat modeling при проектировании новых фич
* автоматические security-проверки в CI (SAST, dependency scan)
* регулярный pentest / bug bounty для критичных релизов

**DevOps / CI/CD (Shift Left + Shift Right):**
* **Shift Left** — SAST, SCA, secret scanning, lint на каждый commit/PR
* **Shift Right** — DAST, runtime protection (RASP/WAF), мониторинг prod
* security gates в pipeline: сборка не проходит при critical/high findings

**SSDLC / SDLC + Security:** Microsoft SDL, OWASP SAMM, BSIMM — зрелые модели встраивания безопасности в процесс разработки.

**Типы security-тестов по моменту проведения:**
* **Design review** — до написания кода
* **Implementation review** — во время разработки
* **Pre-release testing** — перед выкладкой
* **Production monitoring** — после выкладки

**Тестирование общих механизмов безопасности:**

**1. Аутентификация**
* brute-force / lockout после N попыток
* слабые/дефолтные пароли
* безопасное хранение паролей (hash + salt, не plaintext)
* MFA, session timeout, logout

**2. Авторизация и контроль доступа**
* horizontal privilege escalation (доступ к чужим данным)
* vertical privilege escalation (обычный пользователь → admin)
* IDOR (Insecure Direct Object Reference)
* проверка прав на каждый endpoint, не только на UI

**3. Управление сессиями**
* непредсказуемый session ID
* защита cookie: HttpOnly, Secure, SameSite
* invalidation сессии при logout и смене пароля

**4. Ввод данных и injection**
* SQL Injection, XSS, Command Injection, Path Traversal
* валидация на сервере, encoding output

**5. Криптография**
* TLS для передачи данных
* не использовать слабые алгоритмы (MD5, SHA1 для паролей)
* корректное управление ключами и сертификатами

**6. Логирование и мониторинг**
* аудит критичных действий (login, смена прав, доступ к PII)
* логи не содержат паролей и секретов
* алерты на подозрительную активность

**7. Конфигурация и hardening**
* отключены debug-режимы и stack trace для пользователя в prod
* актуальные патчи, минимальные права сервисных аккаунтов
* security headers (CSP, X-Frame-Options, HSTS)

**8. Обработка ошибок**
* пользователю — общее сообщение, без внутренних деталей
* детали — только в защищённых логах

**Regression security testing** — после исправления уязвимости и при каждом релизе повторять ключевые security-тесты, чтобы не вернулись старые проблемы.
