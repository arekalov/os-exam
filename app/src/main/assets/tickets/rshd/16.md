## Схема, особенности работы со схемами PostgreSQL, search_path

### Схемы
**Схема** в PostgreSQL — пространство имён, содержащее таблицы, представления, функции, типы и т.д. Одна база данных может содержать несколько схем, при этом в ним всегда есть схема `public`. Схемы позволяют:
* Организовывать логически объекты (sales, hr, public).
* Управлять доступом: дать права на схему без прав на другие схемы.
* Иметь одинаковые имена таблиц в разных схемах (например, public.orders и sales.orders).
Удалить схему, содержащую объекты, нельзя без `CASCADE`

### search_path
**search_path** — параметр сессии, представляющий последовательность схем, которая будет использована для идентификации объекта, когда используется неполное имя (без явной схемы). Например, `SET search_path TO myschema, public;` — сначала поиск в `myschema`, затем в public. Если объект не найден, возникает ошибка. search_path может включать системную схему `pg_catalog` (неявно, в конце). Первая схема из `search_path` — используется для
создания объектов — текущая. С помощью `$user` в search_path можно автоматически подставлять схему, совпадающую с именем текущего пользователя.
`pg_temp` и `pg_catalog` автоматически добавляются в search_path перед первой указанной схемой (порядок можно переопределить).
