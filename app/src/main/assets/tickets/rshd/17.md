## Управление доступом к данным в PostgreSQL, привилегии, пользователи

Разным категориям пользователей должны предоставляться: разные возможности (в зависимости от их потребностей) для управления различных объектов БД.
Управление доступом строится на **ролях** - именованных наборах привилегий которые могут выступать в качестве пользователей или групп. Привилегии делятся на:
* **Системные** (создание БД, создание ролей, репликация) — задаются при создании роли.
* **Для взаимодействия с объектами** (`SELECT, INSERT, UPDATE, DELETE, TRUNCATE, TRIGGER, CREATE, EXECUTE и др.`).

Привилегии можно давать на схему, что даёт право создавать в ней объекты или использовать существующие, на таблицу, на столбец (ограниченно), на функцию и т.д.

### Пользователи
**Владелец объекта**– обычно пользователь (роль), создавший объект, обладает некоторыми привилегиями для созданного объекта по умолчанию (ALTER, DROP), может `GRANT` права другим ролям
**Пользователь** —  роль с правом логина (`LOGIN`), исползуются для отображения именованных пользователей системы, может быть создан суперпользователем (`SUPERUSER`) и пользователем с ролью `CREATEROLE`. При установке кластера создается администратор postgres.

Для аутентификации пользователей на уровне подключения используется файл `pg_hba.conf` (клиентский IP, база, метод — md5, scram-sha-256, trust, peer и др.)
