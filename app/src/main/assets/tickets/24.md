**Функциональное тестирование** — проверка соответствия функций системы заявленным требованиям и спецификациям. Относится к тестированию «чёрного ящика»: проверяется *что* делает система, а не *как* она это реализует внутри.

**Выбор тестового покрытия** — определение набора тестов, достаточного для проверки всех значимых функций. Основной источник — документация: требования, Use Cases, User Stories, бизнес-правила.

## Подходы к выбору тестов

**1. На основе требований (Requirements-based)**
* Каждому функциональному требованию соответствует ≥ 1 тест-кейс.
* Строится **матрица трассируемости** (Traceability Matrix): строки — требования, столбцы — тесты; на пересечении — покрыто ли требование.
* Позволяет увидеть непокрытые требования и «лишние» тесты без привязки к спецификации.

**2. На основе сценариев использования (Use Case-based)**
* Для каждого Use Case проектируют тесты на:
  * **Основной поток (Main flow)** — успешный сценарий от начала до конца
  * **Альтернативные потоки** — другие допустимые пути (например, оплата картой вместо наличных)
  * **Исключительные потоки** — ошибки, отмены, неверный ввод
* Пример: Use Case «Оформление заказа» → тесты на успешный заказ, недостаток товара, неверный адрес, отмена.

**3. На основе рисков (Risk-based)**
* Не все функции одинаково важны. Приоритет — функциям с высоким риском (часто используются, критичны для бизнеса, сложны в реализации).
* Больше тестов — на «горячие» области; меньше — на второстепенные.

## Шаги применения

1. Изучить требования и Use Cases
2. Выделить функции и бизнес-правила
3. Определить приоритеты (риски)
4. Для каждой функции выбрать техники проектирования: эквивалентность, граничные значения, таблицы решений, диаграммы состояний
5. Составить тест-кейсы и матрицу трассируемости
6. Выполнить тесты, обновить покрытие

## Уровни функционального тестирования

* **Модульное** — отдельные функции/методы
* **Интеграционное** — взаимодействие компонентов (API, модули)
* **Системное** — система целиком в тестовой среде
* **Приёмочное** — соответствие ожиданиям заказчика (UAT)

## Критерии завершения

* Все требования покрыты тестами (100% requirements coverage)
* Пройдены основные и критичные альтернативные потоки Use Cases
* Нет открытых дефектов высокого/критического приоритета

**Отличие от нефункционального:** функциональное — корректность логики (логин, расчёт, отчёт); нефункциональное — производительность, безопасность, удобство, надёжность.
