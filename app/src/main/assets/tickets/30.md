**Доменная модель** — сущности, value objects, бизнес-правила. **Модульное тестирование в JUnit 5** — проверка логики в изоляции от БД, UI, сети.

**Принципы:** изоляция, быстрота, читаемость (`@DisplayName`), независимость.

**Что тестировать:**
* Инварианты сущностей (баланс ≥ 0)
* Бизнес-правила (нельзя снять больше, чем на счёте)
* Value Objects (равенство по значению через `assertEquals`)
* Доменные сервисы (перевод между счетами)
* Исключения через `assertThrows`

**Пример:**

```java
@Test
@DisplayName("Пополнение увеличивает баланс")
void deposit() {
    Account account = new Account("123", 1000);
    account.deposit(500);
    assertEquals(1500, account.getBalance());
}

@Test
@DisplayName("Снятие сверх баланса — исключение")
void withdrawExceedsBalance() {
    Account account = new Account("123", 100);
    assertThrows(InsufficientFundsException.class,
        () -> account.withdraw(200));
}
```

**Зависимости** (репозитории) — mock через Mockito + `@ExtendWith(MockitoExtension.class)`:

```java
@ExtendWith(MockitoExtension.class)
class TransferServiceTest {
    @Mock AccountRepository repository;
    @InjectMocks TransferService service;

    @Test
    void transfer() {
        when(repository.findById("1")).thenReturn(new Account("1", 1000));
        service.transfer("1", "2", 500);
        verify(repository).save(any(Account.class));
    }
}
```

Основа TDD и защита бизнес-логики от регрессий.
