### Понятие HATEOAS.
**HATEOAS** (Hypermedia as the Engine of Application State) — архитектурный принцип, накладывающий ряд дополнительных ограничений на REST-приложения (3 уровень с точки зрения модели Ричардсона), согласно которому сервер возвращает клиенту не только данные ресурса, но и ссылки на доступные действия и связанные ресурсы.  В отличие от SOA, нет обязательного заранее определённого протокола взаимодействия клиента с сервисом

Клиент использует эти ссылки для дальнейшего взаимодействия с API, не определяя все возможные URI самостоятельно, то есть ему не требуется заранее знать,  как взаимодействовать с сервисом за
пределами гипермедиа

### Гипермедиа как часть REST-архитектуры.
**Гипермедиа** — способ организации данных, при котором информация содержит ссылки на другие ресурсы и возможные действия. HATEOAS основан на концепции гипермедиа. В REST гипермедиа является частью ограничения Uniform Interface.

### Использование ссылок для перехода между состояниями приложения.
В HATEOAS взаимодействие строится как последовательность переходов между состояниями приложения. Клиент не обязан заранее знать все возможные адреса и переходы, получая доступные ссылки от сервера и используя их.

**Алгоритм работы HATEOAS**:
1. REST-клиент обращается к фиксированному URL.
2. Все последующие действия определяются “по ходу работы” из возвращаемых сервисом ресурсов.
3. Типы ресурсов, представления и их связи стандартизированы.

### Преимущества и недостатки.
**Преимущества**:
- уменьшается зависимость клиента от внутренней структуры API;
- сервер может изменять URI и доступные действия, сохраняя ссылки в ответах;
- клиенту проще ориентироваться в возможных операциях;
- поддерживается динамическое управление переходами между состояниями приложения.

**Недостатки**:
- усложняется реализация API и клиентской логики;
- увеличивается объём HTTP-ответов из-за дополнительных ссылок;
- требуется единый формат представления гипермедиа;
- не все клиенты и инструменты одинаково хорошо поддерживают HATEOAS.

### Примеры реализации.

**HAL** (Hypertext Application Language) - Формат гипермедиа, использующий поля `_links` (ссылки на текущий ресурс и связанные с ним ресурсы) и `_embedded` (представления связанных ресурсов непосредственно внутри текущего ответа, а не только ссылки на них) В JSON/XML, пример представления:
```json
{
  "_links": {
    "self": {
      "href": "/users/15"
    },
    "orders": {
      "href": "/users/15/orders"
    }
  },
  "id": 15,
  "name": "Alex",
  "_embedded": {
    "orders": [
      {
        "id": 100,
        "total": 1500
      },
      {
        "id": 101,
        "total": 2500
      }
    ]
  }
}
```
