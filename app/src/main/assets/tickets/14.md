## VACUUM

**VACUUM** — процесс очистки «мёртвых» (dead) версий строк, накопившихся из-за MVCC. При UPDATE/DELETE старые версии строк не удаляются сразу — они помечаются как мёртвые и занимают место. VACUUM освобождает это место для повторного использования.

### Зачем нужен VACUUM
* Освобождает место от мёртвых строк (не возвращает OS, но делает доступным для новых данных).
* Обновляет карту видимости (`_vm`) и карту свободного пространства (`_fsm`).
* Обновляет статистику для планировщика запросов.
* Предотвращает **wraparound** — переполнение счётчика транзакций `xid` (32-bit), при котором PostgreSQL перестаёт принимать транзакции.

### Виды VACUUM
* **VACUUM** — очистка без эксклюзивной блокировки, таблица доступна для чтения и записи. Не уменьшает размер файла.
* **VACUUM FULL** — переписывает таблицу целиком, возвращает место OS. Требует эксклюзивной блокировки таблицы — таблица недоступна во время выполнения.
* **VACUUM ANALYZE** — выполняет очистку и обновляет статистику для планировщика.
* **ANALYZE** — только сбор статистики без очистки.

### Autovacuum
**Autovacuum** — фоновый процесс, автоматически запускающий VACUUM и ANALYZE. Управляется параметрами в `postgresql.conf`:
* `autovacuum` — включить/выключить (on по умолчанию).
* `autovacuum_vacuum_scale_factor` — доля мёртвых строк от размера таблицы, при которой запускается очистка (по умолчанию 0.2 = 20%).
* `autovacuum_vacuum_threshold` — минимальное число мёртвых строк для запуска (по умолчанию 50).

```sql
VACUUM mytable;
VACUUM FULL mytable;
VACUUM ANALYZE mytable;
```
