## Quartz
**Quartz** - open-source фреймворк планирования заданий, написанный  на Java и предназначенный для использования в приложениях J2SE и J2EE, часто применяется в паре с Camunda для запуска процессов по расписанию, а также для любых фоновых задач в enterprise-системах (генерация и рассылка отчетов, отправка уведомлений, синхронизация данных). Разделяет работу (**Job**) и расписание (**Trigger**), позволяя гибко связывать несколько триггеров с одной задачей и переиспользовать задачи независимо от их расписания.

## Архитектура
Построена вокруг трёх основных компонентов: 
* планировщика (Scheduler) - управляет жизненным циклом всех задач, для создания используются фабрики Scheduler Factor 
* исполнителя задания (Job) - содержит бизнес-логику
* триггера (Trigger) - определяет время запуска.  (SimpleTrigger, CronTrigger)

Ключевой элемент - **JobStore**, сохраняющий состояние всех заданий и триггеров в памяти или БД.
Также есть интерфейсы **Job Listener** и **Trigger Listener**, реализуемый классами, которые должны реагировать запуск задачи и срабатывание триггера соответственно

## Конфигурация
1. Программная конфигурация (**DirectSchedulerFactory**) - создание и настройку планировщика напрямую через Java код, не требует внешних конфигов, однако все настройки жестко зашиты в коде, что усложняет изменение параметров без перекомпиляции. Например, для тестов
2. Конфиг через properties файл (**StdSchedulerFactor**) - основной способ конфигурации, использует файл `quartz.properties`:
```
org.quartz.scheduler.instanceName = MyScheduler
org.quartz.scheduler.instanceId = AUTO

# Конфигурация пула потоков
org.quartz.threadPool.class = org.quartz.simpl.SimpleThreadPool
org.quartz.threadPool.threadCount = 10

# Конфигурация хранилища заданий (RAM)
org.quartz.jobStore.class = org.quartz.simpl.RAMJobStore
```
Тажке properties может загружаться не из файла, а создаваться программно (из `java.util.Properties` например) или читаться из .env

3. Декларативно через XML с помощью плагина **XMLSchedulingDataProcessorPlugin**, в котором объявляются  Scheduler, Job, Trigger, затем путь к xml файлу настраивается в quartz.properties

## Интеграции в приложения
* Java SE:
  *  добавить quartz в pom.xml
  *  создать класс, реализующий Job и метод execute (HelloWorldJob)
  *  создать планирощик (например через StdSchedulerFactory), job с помощью JobBuilder.newJob(`HelloWorldJob.class`), триггер (`TriggerBuilder.newTrigger()`)
  *  связать job и trigger:  `scheduler.scheduleJob(job, trigger);`
  *  запустить планировщик  `scheduler.start()`

* Spring Boot:
  * Добавить стартер spring-boot-starter-quartz в Spring Boot
  * Создать Job, который может использовать Spring Beans (например сервис): 
  ```java
    @Component
    class ReportGenerationJob extends QuartzJobBean
    ```
  * Сконфигурировать JobDetail и Tringger в Spring-конфиге:
  ```java
  @Configuration
    public class QuartzConfig {

        @Bean
        public JobDetail reportJobDetail() {
            return JobBuilder.newJob(ReportGenerationJob.class) ...
                    .build();
        }

        @Bean
        public Trigger reportJobTrigger(JobDetail reportJobDetail) {
            return TriggerBuilder.newTrigger() ...
                    .build();
        }
    }
    ```
