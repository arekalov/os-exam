## Физическое резервное копирование

**Физическое резервное копирование** — копирование бинарных файлов данных PostgreSQL (каталог PGDATA) «как есть». В отличие от логического, привязано к версии PostgreSQL и архитектуре ОС, но гораздо быстрее восстанавливается для больших БД.

### pg_basebackup

**pg_basebackup** — официальная утилита для создания физической резервной копии работающего кластера по протоколу репликации:
```bash
pg_basebackup -U replicator -D /backup/base -Fp -Xs -P
# -Fp — plain format (копия каталогов)
# -Xs — включить WAL-сегменты в бэкап (stream)
# -P  — показывать прогресс
```
Требует роль с атрибутом `REPLICATION` или суперпользователя. В `pg_hba.conf` нужна запись для репликационного подключения.

### WAL-архивирование и PITR

**WAL-архивирование** — сохранение WAL-сегментов по мере их заполнения в отдельное хранилище. Настраивается в `postgresql.conf`:
```
wal_level = replica
archive_mode = on
archive_command = 'cp %p /archive/%f'
```

**PITR** (Point-in-Time Recovery) — восстановление на любой момент времени с помощью базовой копии + WAL-архива:
1. Развернуть базовую копию в PGDATA.
2. Положить WAL-сегменты в `pg_wal/` или настроить `restore_command`.
3. Создать файл `recovery.signal` и настроить `postgresql.conf`:
```
restore_command = 'cp /archive/%f %p'
recovery_target_time = '2024-01-15 12:00:00'
```
4. Запустить PostgreSQL — он автоматически применит WAL до указанной точки.

### Преимущества и ограничения
* Быстрое восстановление больших БД — не нужно повторно выполнять SQL.
* Поддерживает PITR — восстановление на произвольный момент времени.
* Привязан к версии PostgreSQL и платформе (нельзя восстановить на другой мажорной версии без дополнительных инструментов).
