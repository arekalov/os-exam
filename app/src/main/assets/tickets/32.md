## JCA
**JCA** — Формальная спецификация, стандартная архитектура Jakarta/Java EE для подключения Java-приложений (серверов приложений, приложений, бинов) к корпоративным системам (ERP, CRM, legacy mainframe, CICS), Описывает и позволяет реализовать унифицированные механизмы интеграции между инфраструктурой под управлением сервера приложений и EIS. Частный случай использования – интеграция с легаси- системами.

## JCA Resource Adapters
Компонент JCA - набор классов, стандартизированых и описаных в спецификации Java/Jakarta EE и инкапсулирующих реализацию интерфейса взаимодействия с EIS. Содержат API / SPI для различных способов
взаимодействия с EIS. Могут идти из коробки как часть сервера приложений, либо можно скачать готовые или разрабатывать свои. Взаимодействие с EIS осуществляется в рамках некоторого набора специфицированных функций (контрактов):
* Connection Management - управление соединениями
* Transaction Management - Управление транзакциями, поддержка JTA
* Security Management - Авторизация, делегирование прав, преобразование credentials
* Lifecycle Management - управление ЖЦ
* Work Manager - управление выполнением задач

Адаптеры упаковываются в архивы `*.rar` (**Resource adapter ARchive**), конфигурация задает в дескрипторах развёртывания `ra.xml`. для inbound и outbound-взаимодействия обычно заводятся отдельные адаптеры.

### Интеграция с Jakarta EE
Сервер приложений Jakarta EE берет на себя управление ресурсами через системные контракты: подключение (`Connection Management`), транзакции (`Transaction Management`) и безопасность (`Security Management`) . Адаптер разворачивается в сервере и получает от него эти сервисы автоматически. RAR-архив с адаптером можно развернуть на сервере (JBossEAP, WebLogic), а также в контейнерах JBoss/WildFly управление осуществляет через CLI: `/deploy /path/to/resource-adapter.rar`. В приложении конфигуриется зависимость (например аннотацией `@ConnectionFactorDefinition` с указанием name, interfaceName и resourseAdapter), которую затем можно инжектировать аннотацией @Reourse по определенному ранее name

### Интеграция с Spring
* Поддержка JCA впервые реализована в Spring 2.0.3
* Для inbound-взаимодействия - можно подключаться RA через CDI в бины
* Для outbound-взаимодействия - поддержка JCA Message Endpoints
* API в коде используются те же, что и в Jakarta EE.
