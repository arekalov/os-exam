## Компонентный подход

Бизнес-логика разбивается на независимые компоненты (сервисы), каждый из которых отвечает за свою область задач. Это упрощает сопровождение, тестирование и масштабирование.

В Spring реализуется через `@Service`-бины, каждый из которых инкапсулирует свою часть логики.

## Многопоточность

Бизнес-логика обычно многопоточная — несколько запросов обрабатываются параллельно в разных потоках. Это требует:
- Потокобезопасных компонентов (stateless-сервисы)
- Управления доступом к общим ресурсам (транзакции, блокировки)
- Корректной работы с ThreadLocal (например, SecurityContext в Spring)

## Распределённость

Бизнес-логика может быть размазана по нескольким однородным или неоднородным узлам:
- **Горизонтальное масштабирование** — несколько одинаковых узлов обрабатывают нагрузку
- **Разнородные узлы** — разные части логики на разных сервисах (микросервисы)
- Требует синхронизации: распределённые транзакции, очереди сообщений, согласованность данных
