## Управление бинами в Spring, двухфазный и трёхфазный конструктор

В Spring Framework **управление бинами** — центральный механизм **IoC** (Inversion of Control), при котором контейнер сам создаёт, настраивает и управляет объектами. Жизненный цикл бина включает несколько стадий: 
1. создание экземпляра
2. внедрение зависимостей (через конструктор или сеттеры), 
3. вызовы callback-методов (например, `@PostConstruct`)
4. Использование бина
5. Уничтожение (`@PreDestroy`).

Конфигурация бинов может задаваться разными способами: через XML, Java-конфигурацию (`@Configuration, @Bean`) или аннотации (`@Component, @Service, @Repository`) с автосканированием. В современных проектах чаще всего используют аннотации и Java-конфигурацию.

### Двуфазный и трехфазный конструктор
Если мы в конструкторе бина пытаемся обратиться к каким-то вещам, которые должен настроить Spring, этих вещей на этом этапе еще нет. В таком случае используется двуфазный конструктор. 
Интерфейс **BeanPostProcessor** - позволяет настраивать бины до их попадания в контейнер, имеет 2 метода:
* `Object postProcessBeforeInitialization(Object bean, String beanName)`
* `Object postProcessAfterInitialization(Object bean, String beanName)`
 
Между ними вызывается init-метод,  содержащий логику, использующую объекты, которые должен настроить Spring, и который можно настроить:
* атрибутом init-method в тэге bean
* аннотацией @PostContruct
* afterProperiesSet

Однако например, если вызываемый в init-методе другой метод имеет аннотацию `@Transactional`, то init-метод с @PostConstuct не сможет отработать, т.к. на этапе PostConstruct транзакции (и другие прокси) еще не настроены. Поэтому иногда нужно иметь третью фазу конструктора, которую можно реализовать с помощью `ApplicationListener`. Он умеет слушать контекст Spring (ивенты):
* ContextStarted
* ContextStopped
* ContextRefreshed - вызывается в том числе при завершении построения контекста

Таким образом, можно написать его реализацию, в котором к событию ContextRefreshed привязать вызов методов, использующих прокси-объекты типа @Transactional, которые например, будут помечены кастомной аннотацией

```java
public class PostProxyInvokerContextListener implements ApplicationListener<ContextRefreshedEvent>,
    @Autowired
    private ConfigurableListableBeanFactory factory;
    @Override
    public void onApplicationEvent(ContextRefreshedEvent event) {
        ApplicationContext context = event.getApplicationContext();
        String[] names = context.getBeanDefinitionNames();
        for (String name : names){
            BeanDefinition beanDefinition = factory.getBeanDefinition(name);
            String originalClassName = beanDefinition.getBeanClassName();
               try {
                  Class<?> originalClass = Class.forName(originalClassName);
                  Method[] methods = originalClass.getMethods();
                  for (Method method : methods) {
                      if (method.isAnnotationPresent(Postproxy.class)) {
                          Object bean = context.getBean(name);
                          Method currentMethod = bean.getClass().getMethod(method.getName(), method.getParameterTypes());
                           currentMethod.invoke(bean);
                      }
                  }
              }
        }
    }
```
