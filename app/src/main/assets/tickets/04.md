## Встроенная библиотека внутри приложения
Разрабатывается обычное Java-приложение, и в зависимостях указывается Camunda. БД своя, задачи свои, админка своя, исполнители свои. Удобнее для эксплуатации — следить нужно только за
одной базой и одной камундой, но создает проблему “шумных соседей” —
если кто-то из коллег сделает кривой процесс, то лягут все.

![](images/3_integrated_lib.png)

## Сервис внутри сервера приложений
Сервис внутри сервера приложений или контенейра серверлетов ("расшаренный" сервис), может использоваться другими приложениями, развернутыми в контейнере

![](images/3_shared_service.png)

## Standalone-сервер 
Развернуть Camunda как отдельно стоящий сервер, процессы при этом заливаются на него с помощью war-файлов, приложение(я) будут с ним контактировать по Rest API удаленно. БД, исполнители зада и админка общие. Обладает полной независиомтью, однако создает сложности в администрировании и управлении задачами
