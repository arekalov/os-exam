### Основные компоненты SOA.
Любая SOA-система состоит из трёх видов “блоков”:
* Поставщик (service provider) - компонент, который реализует определённую функциональность и предоставляет её другим приложениям или сервисам:
  * создает веб-службу и предоставляет информацию о ней в реестр службы.
  * Решает, какой сервис предоставлять
  * Решает вопросы безопасности и доступности
  * Обработка поступающих запросов.
* Брокер (broker) / реестр (registry) / репозиторий (repository).
  * Хранение информации о сервисах.
  * Делает информацию о веб-сервисе доступной для любого потенциального
  запрашивающего.
  * Поиск и обнаружение сервисов потребителями.
  * Есть публичные брокеры (доступны всем), и частные (доступные узкому
  кругу лиц)
* Потребитель (requester / consumer) - приложение или другой сервис, который использует функциональность поставщика.
  * Поиск необходимого сервиса.
  * Получение описания его интерфейса.
  * Формирование запросов в соответствии с контрактом.
  * Обработка полученных ответов.

### Взаимодействие компонентов.

Взаимодействие поставщика, потребителя и реестра обычно описывается тремя основными операциями:
1. **Publish/Register** (Публикация) — поставщик регистрирует информацию о сервисе в реестре.
2. **Find** (Обнаружение) — потребитель ищет необходимый сервис в реестре.
3. **Bind** (Связывание) — потребитель получает информацию для подключения и взаимодействует с поставщиком.

### Сервисная шина ESB
**ESB** (Enterprise Service Bus) — программная инфраструктура для интеграции сервисов, обеспечивающая их взаимодействие через единую промежуточную шину, позволяет объединять сервисы, использующие разные протоколы, форматы данных и технологии реализации.

**Основные функции ESB**:
1. **Маршрутизация сообщений** (Message Routing) — определение получателя сообщения и его перенаправление нужному сервису.
2. **Преобразование форматов** (Message Transformation) — преобразование данных из одного формата в другой, например XML в JSON.
3. **Преобразование протоколов** (Protocol Transformation) — обеспечение взаимодействия сервисов, использующих разные протоколы.
4. **Обработка сообщений** — фильтрация, проверка и изменение сообщений.
5. **Обработка ошибок** — управление ошибками при передаче сообщений.
6. **Безопасность** — возможность централизованной настройки аутентификации и авторизации.
7. **Мониторинг** — отслеживание взаимодействия сервисов.

**Преимущества ESB:**
- Упрощение интеграции разнородных систем.
- Централизация маршрутизации и преобразования сообщений.
- Уменьшение количества прямых связей между сервисами.
- Возможность централизованного мониторинга.
  Дополнительные задержки при передаче сообщений.
- Усложнение архитектуры.
- Необходимость обслуживания самой шины.
- Возможность возникновения единой точки отказа при отсутствии резервирования.
- Централизованная шина может стать узким местом при высокой нагрузке.
