**Распределенная обработка в JMS** — механизм асинхронного выполнения задач в гетерогенной среде, использующий спецификацию универсального API Jakarta/Java EE, позволяет абстрагировать прикладной код от низкоуровневых деталей инфраструктурного ПО и протоколов обмена сообщениями (AMQP, OpenWire). За счет этого JMS обеспечивает надежный, слабосвязанный обмен данными между компонентами распределенных приложений через очереди и топики.

### Отправка сообщения:
* Лукапом из контекста получаем ConnectionFactory, с помощью которой создаём соединение Connection, с помощью которого создаём сессию Session.
* Лукапом из контекста вытаскиваем очередь по её имени (объект Destination).
* Создаём из полученной сессии producer, привязанный к очереди и отправляем сообщение: producer.send(message);
 
### Получение сообщения:
* Лукапом из контекста мы получаем ConnectionFactory, с помощью которой создаём соединение Connection, с помощью которого создаём сессию Session.
* Лукапом из контекста вытаскиваем очередь по её имени (объект Destination).
* Создаём из полученной сессии consumer, привязанный к очереди. Создаем объект MessageListener и сетим его консьюмеру: consumer.setMessageListener(listener);

## Уровни гарантии доставки сообщений
* надежная доставка сообщений (reliable) - система гарантирует, что в процессе обмена сообщениями ни один сетевой пакет не будет потерян;
* гарантированная доставка сообщений (guaranteed) - сообщение доставляется адресату немедленно или через заданный промежуток времени, не превышающий определенного значения (в случае, если сеть в данный момент не доступна);
* застрахованная доставка сообщений (assured) - самая строгая гарантия: каждое сообщение доставляется только один раз.
