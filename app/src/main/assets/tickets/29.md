## Интеграция ИС
Интеграция информационных систем — процесс объединения разрозненных приложений, сервисов и данных в единую согласованную экосистему, позволяющую им обмениваться информацией и совместно выполнять бизнес-операции. Существует три основных подхода к интеграции, которые часто комбинируются:

### Использование паттернов интеграции
Применение проверенных архитектурных шаблонов, описывающих типовые способы взаимодействия между компонентами систем. Одним из них является паттерн **Адаптер** - структурный паттерн, преобразующий интерфейс одной системы в интерфейс, ожидаемый другой системой. В контексте интеграции адаптер решает проблему протокольной и интерфейсной несовместимости. Пример использования: адаптер, слушающий очередь и преобразующий JMS-сообщения в вызовы legacy-системы, не поддерживающей JMS. В качестве других примеров интеграции можно привести **Транслятор сообщений**, используемый для преобразования структуры сообщения из одного формата в другой, и **Content-Based Router**, используемый для того, чтобы направить сообщения в разные очереди или разным потребителям в зависимости от содержимого сообщения.

### Использование инфраструктурных решений
Внедрение промежуточного ПО (middleware) — специализированной инфраструктуры, которая берет на себя маршрутизацию, трансформацию, хранение, безопасность и управление сообщениями. Приложения перестают знать друг о друге и общаются только через этот слой. Типы инфраструктурных решений:
* **Брокеры сообщений** (ActiveMQ, RabbitMQ) - маршрутизация, очереди, топики, гарантии доставки
* **Enterprise Service Bus** (Mule ESB, Apache ServiceMix) - более тяжеловесный, чем просто брокер сообщений, может также включать оркестрацию, адаптеры и прочее
  
Решений достаточно много, однако подход зачастую требует доработки интегрируемой ИС и не всегда применим

### Использование формальных спецификаций и их реализаций
Применение стандартизированных, переносимых способов подключения приложений к корпоративным ИС. Вместо написания уникального кода для каждой системы разработчик использует готовый, сертифицированный коннектор, реализующий спецификацию **JCA** (Jakarta Connectors Architecture).

**JCA** — стандартная архитектура Jakarta/Java EE для подключения Java-приложений (серверов приложений, приложений, бинов) к корпоративным системам (ERP, CRM, legacy mainframe, CICS), Описывает и позволяет реализовать унифицированные механизмы интеграции между инфраструктурой под управлением сервера приложений и EIS.
**Основные компоненты JCA:**
* Resourse Adapter - Переносимая реализация специфики конкретной EIS, как драйвер БД, но для ИС
* Application Server Contract - cтандартный способ взаимодействия между контейнером Jakarta EE и коннектором (управление соединениями, транзакциями, безопасностью)
* Connection Management - Пул соединений к EIS
* Transaction Management - Интеграция с JTA  для распределенных транзакций
* Security Management - Авторизация, делегирование прав, преобразование credentials
* Client API - Интерфейс для приложения, может быть специфичным для коннектора

Примеры: JBoss IronJacamer, WebLogic JCA Adapter
