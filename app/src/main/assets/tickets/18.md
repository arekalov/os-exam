## UNDO-журнал

**UNDO-журнал** — журнал, хранящий **до-образы** (before-images) страниц или строк до их изменения. Используется для отката (ROLLBACK) незавершённых транзакций и для восстановления после сбоя при политике **steal** (когда незафиксированные изменения могут быть записаны на диск).

### Принцип работы

Перед изменением данных в UNDO-журнал записывается старое значение. Если транзакция откатывается — применяются до-образы, восстанавливая данные в исходное состояние.

**Правило записи:** UNDO-запись должна быть записана на диск **до** того, как изменённая страница попадёт на диск (иначе при сбое нечем откатить).

### Структура записи в UNDO-журнале
* Идентификатор транзакции.
* Идентификатор изменённого объекта (таблица, страница, строка).
* Старое значение данных (before-image).
* LSN (Log Sequence Number) для связи с позицией в журнале.

### Алгоритм отката
При откате транзакции записи читаются в **обратном порядке**, и для каждого изменения применяется до-образ. При использовании ARIES каждая операция отката записывается как CLR (Compensation Log Record) — чтобы при повторном сбое не откатывать уже откаченное.

### В PostgreSQL
PostgreSQL не ведёт классический UNDO-журнал. Вместо этого старые версии строк хранятся прямо в страницах таблицы (heap) рядом с новыми версиями — это и есть механизм MVCC. При откате PostgreSQL просто помечает версии строк как недействительные через `xmax`, а очищаются они позднее через VACUUM.
