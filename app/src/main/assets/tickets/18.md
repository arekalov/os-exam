## Назначение и архитектура

**Spring Web MVC** — веб-фреймворк Spring на основе Servlet API. Применяется для серверных веб-приложений и RESTful-сервисов. Центральный компонент — `DispatcherServlet`, который принимает запросы и направляет их контроллерам.

Архитектура **MVC** разделяет обязанности:

- **Model** — данные приложения и результаты обработки.
- **View** — отображение данных модели, например HTML-страница.
- **Controller** — обработка HTTP-запроса, обращение к бизнес-логике и формирование результата.

В REST-сервисе контроллер возвращает данные ресурса, обычно JSON или XML. Вместо рендеринга HTML объект сериализуется через `HttpMessageConverter`.

## REST-контроллеры

`@RestController` объединяет `@Controller` и `@ResponseBody`: результаты методов записываются в тело HTTP-ответа. `@RequestMapping` и специализированные аннотации связывают URL и HTTP-методы с обработчиками.

Spring поддерживает внедрение зависимостей, преобразование параметров, валидацию, обработку исключений и согласование формата ответа. `ResponseEntity` позволяет задать тело, статус и заголовки. Бизнес-логика обычно выносится из контроллера в сервисный слой.

## Сравнение с JAX-RS

Оба подхода используют аннотации для маршрутизации запросов, извлечения параметров и преобразования тел сообщений.

- **JAX-RS** — спецификация Jakarta EE; реализации — Jersey, RESTEasy. Использует `@Path`, `@GET`, `@POST`, `@Consumes`, `@Produces`.
- **Spring Web MVC** — конкретный фреймворк экосистемы Spring. Использует `@RestController`, `@GetMapping`, `@PostMapping`, `@RequestBody`.
- В JAX-RS преобразование тела выполняют провайдеры `MessageBodyReader` / `MessageBodyWriter`, в Spring MVC — `HttpMessageConverter`.
- Spring MVC поддерживает и REST API, и обычные MVC-представления; JAX-RS ориентирован на RESTful веб-сервисы.
