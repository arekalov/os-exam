## REDO-журнал

**REDO-журнал** — журнал, хранящий **после-образы** (after-images) изменений. Используется для повтора зафиксированных транзакций при восстановлении после сбоя при политике **no-force** (когда страницы могут не быть записаны на диск до COMMIT).

### Принцип работы

Перед записью изменённой страницы на диск в журнал записывается новое значение. После сбоя — все зафиксированные транзакции повторяются по журналу, восстанавливая потерянные изменения.

**Правило записи (Write-Ahead Logging, WAL):** REDO-запись должна быть записана на диск **до** того, как изменённая страница попадёт на диск. Это гарантирует, что при сбое всегда есть что воспроизвести.

### Структура записи в REDO-журнале
* LSN (Log Sequence Number) — уникальный монотонно возрастающий номер позиции в журнале.
* Идентификатор транзакции.
* Идентификатор объекта (таблица, страница).
* Новое значение данных (after-image) или описание операции (redo-action).

### Контрольная точка (Checkpoint)
**Checkpoint** — момент, когда все «грязные» страницы из буферного кэша принудительно сбрасываются на диск. После checkpoint для восстановления нужно повторить только записи журнала **начиная с этой точки** — это ускоряет восстановление. Параметры: `checkpoint_timeout`, `max_wal_size`.

### WAL в PostgreSQL
PostgreSQL реализует REDO через **WAL** (Write-Ahead Log, журнал предзаписи). WAL-файлы хранятся в `PGDATA/pg_wal/`. Каждая страница данных содержит LSN последнего изменения — при восстановлении страницы с LSN >= LSN записи в WAL не перезаписываются (идемпотентность redo). WAL используется также для репликации (streaming replication) и PITR.
