## Основные компоненты

- **DispatcherServlet** — входной сервлет, координирующий обработку запросов по шаблону Front Controller.
- **HandlerMapping** — находит обработчик по пути, HTTP-методу, параметрам и заголовкам. Для аннотированных контроллеров используется `RequestMappingHandlerMapping`.
- **HandlerAdapter** — вызывает найденный обработчик. `RequestMappingHandlerAdapter` подготавливает аргументы метода контроллера и обрабатывает его результат.
- **Controller** — принимает параметры, вызывает сервисный слой и возвращает результат.
- **ViewResolver** — преобразует логическое имя представления в объект `View`, например шаблон HTML.
- **HttpMessageConverter** — читает тело запроса в Java-объект и записывает Java-объект в тело ответа.

## Обработка REST-запроса

1. HTTP-запрос поступает в `DispatcherServlet`.
2. `HandlerMapping` выбирает метод контроллера и связанные перехватчики.
3. `HandlerAdapter` подготавливает аргументы: извлекает значения из URL, параметров и заголовков; для `@RequestBody` использует конвертер тела сообщения.
4. Вызывается метод контроллера, который обращается к бизнес-логике и возвращает объект или `ResponseEntity`.
5. Обработчик возвращаемого значения выбирает подходящий `HttpMessageConverter` с учётом типа объекта и согласованного формата.
6. Конвертер сериализует объект; клиент получает HTTP-статус, заголовки и тело ответа.

Для `@ResponseBody` и `@RestController` поиск представления через `ViewResolver` не требуется. В обычном MVC контроллер возвращает модель и имя представления, после чего `ViewResolver` находит `View`, а оно формирует HTML.

Исключения обрабатываются механизмом `HandlerExceptionResolver`, включая методы с `@ExceptionHandler`.
