## Виды ресурсов

**Ресурс коллекции** — `/users`. `GET` возвращает список, `POST` создаёт объект. При поддержке репозиторием доступны пагинация и сортировка: `?page=0&size=20&sort=name,asc`.

**Ресурс элемента** — `/users/{id}`. `GET` читает объект, `PUT` заменяет, `PATCH` частично обновляет, `DELETE` удаляет. Доступность операций определяется методами репозитория и настройками экспорта.

**Ресурс ассоциации** — `/users/{id}/roles`. Представляет связь между сущностями. `GET` читает связь, `PUT` заменяет её, `POST` добавляет элементы в связь-коллекцию, `DELETE` удаляет связь или её элемент. Для установления связей используются URI связанных ресурсов, например тело типа `text/uri-list`. Удаление связи не означает удаление самой связанной сущности.

**Поисковые ресурсы** — `/users/search` содержит ссылки на экспортируемые запросы. Конкретный поиск вызывается через `GET /users/search/findByName?name=Ann`; параметры соответствуют аргументам метода репозитория.

## HAL и HATEOAS

**HAL (Hypertext Application Language)** — формат представления ресурсов со ссылками. В JSON свойства объекта дополняются:

- **`_links`** — ссылками с именами отношений: `self`, `search`, `profile`, ссылки на ассоциации и страницы;
- **`_embedded`** — встроенными ресурсами, например элементами коллекции.

```json
{
  "name": "Ann",
  "_links": {
    "self": {"href": "/users/1"},
    "roles": {"href": "/users/1/roles"}
  }
}
```

Spring Data REST автоматически формирует ссылки. Это поддерживает **HATEOAS**: клиент обнаруживает доступные переходы по отношениям в ответах сервера.

## Автоматическое описание

Ссылка **`profile`** ведёт к метаданным API. `/profile` содержит ссылки на профили репозиториев, например `/profile/users`.

**ALPS (Application-Level Profile Semantics)** описывает смысл полей и переходов ресурса: атрибуты, операции и параметры. Эти метаданные генерируются на основе экспортируемой модели. HAL описывает конкретное представление со ссылками, а ALPS — семантику соответствующего типа ресурса.
